SleepCare

An IoT health system built around the harder half of the problem: getting a continuous signal to a browser without losing it.

RoleDesign, build and instrumentation
StackESP32-S3 · Socket.IO · 1D-CNN · ChromaDB RAG · Supabase · MERN
One lineFive physiological sensors, streaming, classified in real time.
CodeGitHub ↗

The problem

Sleep data is only useful continuously, and continuous streams break — buffering, dropped sockets, clinicians looking at stale numbers.

What I built

  1. An ESP32-S3 rig integrating five physiological sensors, streaming ten-second buffered windows for ECG cardiac event processing.
  2. A 1D-CNN arrhythmia classifier trained on the cardiac stream, with EEG-based sleep staging across Alpha, Beta, Gamma and RMS bands.
  3. Live Socket.IO broadcasting across four clinical modes with real-time alerting.
  4. RAG-based session querying over ChromaDB so a past night can be asked about in plain language, plus four Excel export pipelines.

What changed

  1. Continuous multi-sensor telemetry surfaced live rather than after the fact.
  2. Arrhythmia detection and sleep staging computed on the stream, not in a batch job.
  3. Clinicians can query a past session in plain language and export it.

AutoDraft

An agent that plans its own steps, calls tools for grounding, and renders a formatted .docx — with a validator between every stage.

RoleDesign, build and instrumentation
StackFastAPI · Groq · Pydantic · python-docx · Tool calling
One lineA request in English, a finished business document out.
CodeGitHub ↗

The problem

Most document generators are one prompt and a prayer. The model invents figures, the structure drifts, and there is no point at which anything is checked.

What I built

  1. A planner turns the request into an ordered task list with its assumptions written down, so the plan can be read before anything is drafted.
  2. An executor decides which tools to call — document template, client profile, market benchmark, current date — and drafts each section grounded in what came back.
  3. Every stage output is validated against a Pydantic schema before the next stage is allowed to run; a malformed plan fails loudly instead of quietly producing a bad document.
  4. A builder renders the validated content into a polished .docx with python-docx, plus an offline fallback mode so the pipeline is demonstrable without a key.

What changed

  1. The document is grounded in tool output rather than model memory.
  2. Failures surface at the schema boundary, not in the finished file.
  3. Two demo cases, including a deliberately ambiguous multi-audience request.

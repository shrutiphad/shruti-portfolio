AI Phone Receptionist

A multi-tenant operations platform for budget hotels: voice and text reception, bookings, and a plain-English window onto the property's own data.

RoleDesign, build and instrumentation
StackFastAPI · Anthropic Claude · PostgreSQL RLS · asyncpg · React + Vite · Docker Compose
One lineTwo hotels, one tenant-isolated brain, sub-millisecond routing.
CodeGitHub ↗

The problem

Budget hotels lose bookings at the front desk — nobody picks up, nobody logs it, and the property management system is a place data goes to die rather than a place anyone asks questions of.

What I built

  1. A two-stage message pipeline: a rules-based classifier answers in under a millisecond and only falls through to Claude when the rules are not confident — cost and latency spent where they earn their keep.
  2. Classified messages drop into asyncio task queues feeding workflow handlers, so a slow downstream call never blocks the reception path.
  3. Tenant isolation enforced in PostgreSQL with row-level security, not in application code — two seeded properties can never read each other's rows even if a query is wrong.
  4. NL-to-SQL over the property's own tables, so an operator asks for occupancy in English instead of learning the schema.
  5. A React + Vite console polling events and bookings on an eight-second cycle, with a mock OTA server standing in for rate and availability feeds.

What changed

  1. Reception, bookings and reporting behind one multi-tenant service.
  2. The expensive model only runs on the messages the cheap path could not resolve.
  3. Tenant isolation is a database guarantee, not a code review promise.

Revenue Attribution Pipeline

The founders had conversation volume and they had revenue, and nothing credible connecting the two.

RoleDesign, build and instrumentation
Stackn8n · Supabase · Razorpay · WhatsApp / Instagram / Messenger · Sagepilot agent
One lineOne trace from first message to paid order, across three channels.

The problem

A person rebuilt the same daily report by hand every morning from three inboxes and a payments dashboard. It arrived late, it disagreed with itself week to week, and no one could say which channel or which conversation had produced an order.

What I built

  1. Modelled the funnel first: the events worth capturing, the identity that stitches a WhatsApp thread to a Razorpay order, and a definition of an attributed sale everyone could sign off on.
  2. Scheduled n8n flows pulling conversations, agent handoffs and payment webhooks into Supabase, with ticket routing and escalation logic living in the pipeline rather than in someone's head.
  3. Instrumented the Sagepilot AI agent alongside human handling so both appear in the same trace and can be compared honestly.
  4. Built an intent and objection taxonomy over the same store, from multilingual chat across four product lines — so an objection could be counted against orders lost.
  5. Published the daily report off that store, so the number in the morning message and the number in the database are the same number.

What changed

  1. 600+ daily conversations across three channels flowing into one reproducible revenue trace.
  2. Manual assembly removed from the daily report entirely.
  3. Cash-on-delivery friction identified as the dominant blocker to first purchase — a checkout problem no sales script could fix.
  4. Channel and agent performance became a query instead of an argument.
